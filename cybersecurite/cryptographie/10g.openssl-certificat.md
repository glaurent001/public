# 1. Créer une demande de signature de certificat (CSR)
**Générer une paire de clés RSA** 2048 bits. La clé privée est essentielle pour sécuriser le certificat.
```sh
openssl genpkey -algorithm RSA -out clé_privée.pem -pkeyopt rsa_keygen_bits:2048
```
ou en version condensée :
```sh
openssl genrsa -out clé_privée.pem 2048
```

**Créer une demande de signature de certificat (CSR)** :
```sh
openssl req -new -key clé_privée.pem -out demande.csr
```
Un CSR contient des informations sur l'organisation et le domaine à certifier. Ces informations constituent le `subject` du CSR. Chaque détail du subject est associée à un acronyme.

* Country Name (2 letter code) [AU]: --> **C**
* State or Province Name (full name) [Some-State]: --> **ST**
* Locality Name (eg, city) []: --> **L**
* Organization Name (eg, company) [Internet Widgits Pty Ltd]: --> **O**
* Organizational Unit Name (eg, section) []: --> **OU**
* Common Name (e.g. server FQDN or YOUR name) []: --> **CN**
* Email Address []:

_Remarque :_ tout n'est pas obligatoire, mais il y a au moins le CN.

_Exemple :_
* certificat de Sectigo : Subject: C=GB, ST=Greater Manchester, L=Salford, O=Sectigo Limited, CN=Sectigo RSA Domain Validation Secure Server CA
* certificat de marmiton.org : Subject: CN=*.marmiton.org

**Pour examiner et vérifier le fichier CSR créé :**
```sh
openssl req -text -in demande.csr -verify -noout
```

# 2. Créer un certificat auto-signé
> ⚠️ Attention : les certificats auto-signés ne sont pas idéaux pour une utilisation en production car il n’y a pas de tierce partie fiable pour vérifier l’identité de l’utilisateur. **Ils doivent servir uniquement aux tests**.

A partir d'un CSR :
```sh
openssl x509 -req -in demande.csr -signkey clé_privée.pem -out certificat.crt -days 365
```
Note :
* -req : Utilise le CSR pour générer le certificat.
* -days 365 : Durée de validité (365 jours).
* -signkey clé_privée.pem : Utilise la clé privée pour signer le certificat.
* -out certificat.crt : Fichier de sortie pour le certificat.


# 3. Vérification de la validité et du contenu du certificat 
La commande suivante affiche les détails d'un certificat pour vérifier son intégrité

```sh
openssl x509 -in certificat.crt -text -noout
```
Vous pourrez vérifier :
* Le sujet (subject): correspond à l'entité à laquelle le certificat est destiné.
* L’émetteur (issuer): l’autorité de certification ayant signé le certificat.
* Les dates de validité : pour s’assurer qu’il n’est ni expiré ni futur.
* La signature : confirme que le certificat est signé correctement


# 4. Vérifier la chaîne de certificats
Pour vérifier si un certificat `certificat.crt` est bien signé par une autorité de certification (CA) et si la chaîne de certificats est correcte, utilisez :
```sh
openssl verify -CAfile chaine_CA.pem certificat.crt
```

Si l'autorité de certification (CA) est une autorité intermédiaire, vous devez fournir la chaîne complète de certificats pour effectuer la vérification. 

Vous devez assembler les certificats dans un seul fichier `chaine_CA.pem`, dans l'ordre suivant :
* Certificat intermédiaire (en premier).
* Certificat racine (en dernier).

Pour créer le fichier `chaine_CA.pem`, utilisez les commandes suivantes :

Sous linux :
```sh
cat certificat_intermediaire.pem certificat_racine.pem > chaine_CA.pem
```

Sous Windows CMD :
```sh
type certificat_intermediaire.pem certificat_racine.pem > chaine_CA.pem
```

# 5. Extraire la clé publique du certificat
Extraire la clé publique **au format PEM** (texte encodé en Base64)
```sh
openssl x509 -in certificat.crt -pubkey -noout > public_key.pem
```

**Convertir** une clé publique PEM **au format DER** (format binaire non encodée en Base64)
```sh
openssl pkey -pubin -in public_key.pem -outform DER -out public_key.der
```

**Convertir** une clé publique du format DER (binaire) **au format PEM** (Base64 encodé lisible)
```sh
openssl pkey -pubin -inform DER -in public_key.der -outform PEM -out public_key.pem
```



# 6. format des fichiers CRT
Les fichiers .CRT peuvent être encodés dans différents formats :
* **PEM (Base64)** : Le plus courant. Ils commencent et se terminent par des lignes :
  ```txt
  -----BEGIN CERTIFICATE-----
  (données encodées en Base64)
  -----END CERTIFICATE-----
  ```
* **DER (binaire)** : Format binaire utilisé par certaines applications spécifiques

Convertir un certificat .CRT vers .DER :
```
openssl x509 -in certificat.crt -outform DER -out certificat.der
```
Convertir un certificat .DER vers .CRT :
```
openssl x509 -in certificat.der -inform DER -out certificat.pem
```
