## 1. Principe de la communication

L'ESP32 joue le rôle de **client HTTP**. Il envoie l'état de la barrière au serveur PHP via une requête **POST**.

```
ESP32                                      Serveur PHP
  │                                                  │
  │──── POST http://addr_ip/api/ ───────────────────►│
  │     Header : X-Api-Key: ma_cle                   │
  │     Body   : {"device_id":"1","etat":"ouvert"}   │
  │                                                  │
  │◄─── {"status":"ok","message":"Log enregistré"} ──│
```

## 2. Le modèle TCP/IP et les bibliothèques ESP32

| Couche | Protocole | Bibliothèque Arduino | Rôle |
|---|---|---|---|
| **Application** | HTTP | `HTTPClient` | Formate les requêtes (GET, POST, headers, body...) |
| **Transport** | TCP | `WiFiClient` | Ouvre un socket TCP, garantit la livraison des données |
| **Internet** | IP | Pile TCP/IP ESP-IDF *(Espressif)* | Achemine les paquets de l'ESP32 jusqu'au serveur |
| **Accès réseau** *(couches 1 et 2)* | WiFi 802.11 | `WiFi.begin()` | Associe l'ESP32 au point d'accès, gère les trames radio |

> **Remarque :** En HTTP (sans TLS), la bibliothèque `WiFiClientSecure` n'est pas nécessaire. `HTTPClient` s'appuie directement sur `WiFiClient` pour ouvrir un socket TCP classique.

> **Différence avec HTTPS :** En HTTPS, une couche TLS s'intercale entre Transport et Application, gérée par `WiFiClientSecure`. En HTTP, cette couche est absente — les données transitent en clair sur le réseau.

## 3. Les bibliothèques utilisées

### `WiFi.h`
Gère la connexion au point d'accès WiFi (couche accès réseau). Fournit `WiFi.begin()`, `WiFi.status()`, `WiFi.reconnect()`...

Cette bibliothèque inclut également `WiFiClient` (socket TCP, couche transport) et `WiFiClientSecure` (socket TCP + TLS). L'inclusion de `WiFi.h` dans le code suffit à les rendre disponibles.

### `HTTPClient.h`
Gère le protocole HTTP : construction de la requête (méthode, URL, headers, body), envoi, lecture de la réponse et du code de statut.

### `ArduinoJson.h`

ArduinoJson est une bibliothèque qui permet de **créer et lire des données JSON** sur microcontrôleur, de façon simple et économe en mémoire.

Dans ce projet, on l'utilise pour construire le corps de la requête POST :

```cpp
JsonDocument doc;          // crée un document JSON vide
doc["device_id"] = "1";    // ajoute une paire clé/valeur
doc["etat"]      = "ouvert";

String body;               // chaîne qui recevra le JSON
serializeJson(doc, body);  // sérialise le document → body = {"device_id":"1","etat":"ouvert"}
```

> **Pourquoi ne pas construire le JSON à la main ?**  
> Une concaténation de chaînes (`"{\"etat\":\"" + etat + "\"}"`) fonctionne pour des cas simples, mais devient vite source d'erreurs (guillemets oubliés, caractères spéciaux non échappés). ArduinoJson gère ces cas automatiquement.

**Installation dans PlatformIO** :

Cherchez et installez la bibliothèque ArduinoJson by Benoit Blanchon.

## 4. La clé API dans le header HTTP

L'authentification repose sur une **clé API** transmise dans un **header HTTP personnalisé** `X-Api-Key`.

Un header HTTP est une ligne de métadonnées ajoutée à la requête, séparée du corps (body). Le serveur PHP le lit via `$_SERVER['HTTP_X_API_KEY']`.

```
POST /api/ HTTP/1.1
Host: 192.168.1.10
Content-Type: application/json
X-Api-Key: cle_entree_nord_2026          ← header d'authentification
Content-Length: 35

{"device_id":"1","etat":"ouvert"}        ← body (données métier)
```

> **Pourquoi dans le header plutôt que dans le body JSON ?**  
> Le header transporte les informations *sur* la requête (qui parle, comment, avec quelle autorisation). Le body transporte les *données métier*. Mélanger les deux rendrait le code moins lisible et poserait problème pour les requêtes GET qui n'ont pas de body.

Dans le code ESP32 :

```cpp
http.addHeader("Content-Type", "application/json");
http.addHeader("X-Api-Key", API_KEY);
```

## 5. Code ESP32 complet

```cpp
#include <Arduino.h>
#include <WiFi.h>
#include <HTTPClient.h>
#include <ArduinoJson.h>

// ── Réseau ────────────────────────────────────────────────────────────
const char* SSID     = "NomDuWifi";
const char* PASSWORD = "MotDePasse";

// ── API ───────────────────────────────────────────────────────────────
const char* API_URL = "http://addr_ip/api/";
const char* API_KEY = "cle_entree_nord_2026";

// ── Fonction d'envoi ──────────────────────────────────────────────────
void envoyerEtat(const String p_etat)
{

  // Couche Transport : création du socket TCP
  WiFiClient clientTCP;

  // Couche Application : création de la requête HTTP
  HTTPClient http;
  http.begin(clientTCP, API_URL);

  // Ajout des headers
  http.addHeader("Content-Type", "application/json");
  http.addHeader("X-Api-Key", API_KEY); // Clé dans le header HTTP

  // Construction du JSON avec ArduinoJson
  JsonDocument doc;
  doc["device_id"] = "1";
  doc["etat"] = p_etat; // "ouvert" ou "ferme"

  String body;
  serializeJson(doc, body);

  // Envoi de la requête POST
  int code = http.POST(body);
  Serial.printf("Code HTTP : %d\n", code);

  if (code > 0)
  {
    // Lecture de la réponse JSON du serveur
    String reponse = http.getString();
    Serial.println(reponse);
  }
  else
  {
    Serial.printf("Erreur : %s\n", HTTPClient::errorToString(code).c_str());
  }

  http.end(); // libère les ressources
}

// ── Setup ─────────────────────────────────────────────────────────────
void setup() {
    Serial.begin(115200);

    // Couche Accès Réseau : connexion au point d'accès WiFi
    WiFi.begin(SSID, PASSWORD);
    Serial.print("Connexion WiFi");
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }
  // Quand on est connecté au réseau WiFi, le serveur DHCP attribue automatiquement la configuration IP
  Serial.println("Connection établie !");
  Serial.println("Adresse MAC ESP = " + WiFi.macAddress());
  Serial.println("Adresse IP ESP = " + WiFi.localIP().toString());
  Serial.println("Masque ESP = " + WiFi.subnetMask().toString());
  Serial.println("Passerelle ESP = " + WiFi.gatewayIP().toString());
  Serial.println("DNS1 ESP = " + WiFi.dnsIP(0).toString());
  Serial.println();
}

// ── Loop ──────────────────────────────────────────────────────────────
void loop() {
    if (WiFi.status() == WL_CONNECTED) {
        envoyerEtat("ouvert");
    } else {
        // Tentative de reconnexion si le WiFi est perdu
        Serial.println("WiFi perdu, reconnexion...");
        WiFi.reconnect();
        delay(5000);   // attend 5s avant de retenter
    }

    delay(10000);   // envoie un état toutes les 10 secondes
}
```

## 7. Codes de retour HTTPClient

| Code | Signification |
|---|---|
| > 0 | Code HTTP reçu du serveur (200, 201, 400, 403...) |
| -1 | `HTTPC_ERROR_CONNECTION_REFUSED` — serveur inaccessible |
| -3 | `HTTPC_ERROR_SEND_PAYLOAD_FAILED` — erreur d'envoi |
| -11 | `HTTPC_ERROR_NOT_CONNECTED` — pas de connexion TCP |

> Les codes négatifs sont des erreurs **réseau** (avant même d'atteindre le serveur). Les codes positifs sont des codes **HTTP** renvoyés par le serveur PHP.

## 8. HTTP vs HTTPS — Récapitulatif

| | HTTP | HTTPS |
|---|---|---|
| Chiffrement | ❌ | ✅ TLS |
| Clé API protégée | ❌ | ✅ |
| Vérification serveur | ❌ | ✅ via certificat CA |
| Bibliothèque socket | `WiFiClient` | `WiFiClientSecure` |
| Complexité | Simple | Nécessite un certificat |
