# 1. Prérequis
Avant d'utiliser ce tuto, assurez vous d'avoir :
* Installé Ubuntu
* Mis à jour l'OS : `sudo apt update && sudo apt upgrade`

> **Remarque** : Dans ce tuto, j'utilise Ubuntu 24.04.4 LTS dans une VM virtualbox\
> -utilisateur : admin-a01\
> -nom de machine : admin-a01-VirtualBox\
> -addresse IP de la VM Ubuntu : 172.16.111.87 (client DHCP)


# 2. Installer un serveur SSH
## 2.1. Installation de OpenSSH

```bash
$ sudo apt install openssh-server
```
Pour démarrer le serveur SSH, il faut utiliser les commandes :

```bash
$ sudo systemctl start ssh
$ sudo systemctl enable ssh
```

> **start** → démarre le service maintenant\
> **enable** → configure le service pour qu'il démarre automatiquement au prochain boot

Vérifiez que le service fonctionne :

```bash
$ sudo systemctl status ssh
```
Le résultat de cette commande doit indiquer :
```text
* Active: active (running)  ← état actuel (start)
* Loaded: enabled           ← configuré au boot (enable)
```
Affichez la version installée :
```bash
$ ssh -V
OpenSSH_9.6p1 Ubuntu-3ubuntu13.15, OpenSSL 3.0.13 30 Jan 2024

```
## 2.2. Configuration minimum

Éditez le fichier de config du serveur ssh :

```bash
$ sudo nano /etc/ssh/sshd_config
```

Vérifiez que ssh utilise les authentification PAM
```conf
UsePAM yes
```
désactivez les accès root :
```conf
PermitRootLogin no
```

et ajoutez les utilisateurs autorisés à se connecter en SSH :
```conf
AllowUsers admin-a01
```

> **Remarque sur la gestion des accès ssh :**\
> SSH évalue les autorisations d'accès grâce à 4 directives :\
> ```DenyUsers  →  AllowUsers  →  DenyGroups  →  AllowGroups```\
> OpenSSH parcourt ces directives dans cet ordre, et s'arrête dès qu'une règle correspond.
> * `AllowUsers` = **Liste blanche** : seuls les utilisateurs listés peuvent se connecter ; tous les autres sont refusés
> * `DenyUsers` = **Liste noire** : les utilisateurs listés sont refusés ; les autres ne sont pas affectés par cette directive seule
> 
> Dès que **`AllowUsers`** est présent dans la config, **tout utilisateur absent de cette liste est implicitement refusé**. Il n'est donc généralement pas nécessaire de combiner `DenyUsers` + `AllowUsers`, sauf pour exclure explicitement un utilisateur qui serait autrement dans un groupe autorisé via `AllowGroups`.
>
> 📌 **Recommandation cybersécurité :**\
> En production, privilégier AllowUsers (whitelist stricte) plutôt que DenyUsers (blacklist).\
> _Une blacklist est fragile : un nouvel utilisateur système créé ultérieurement sera autorisé par défaut. Une whitelist refuse tout ce qui n'est pas explicitement permis — principe du moindre privilège._


## 2.3. Appliquer les changements

```bash
$ sudo systemctl restart ssh
```

## 2.4. Accès à distance
Les accès ssh depuis une autre machine se feront grâce à :

```bash
$ ssh admin-a01@IP_DU_SERVEUR
```
