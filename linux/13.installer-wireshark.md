# 1. Mise à jour du système

Avant toute installation, mettre le système à jour :

```bash
sudo apt update && sudo apt upgrade -y
```

---

# 2. Installation de Wireshark

```bash
sudo apt install wireshark -y
```

Durant l'installation, une boîte de dialogue demande :

> **"Should non-superusers be able to capture packets?"**

- **`Yes`** → recommandé en environnement pédagogique (voir remarques de sécurité ci-dessous)
- `No` → seul root peut capturer (plus restrictif)

Si tu as répondu `No` et souhaites changer :

```bash
sudo dpkg-reconfigure wireshark-common
```

---

# 3. Autoriser la capture sans root (groupe `wireshark`)

Si tu as répondu `Yes` à l'étape précédente, ajoute ton utilisateur au groupe `wireshark` :

```bash
sudo usermod -aG wireshark $USER
```

> ⚠️ **Un redémarrage est recommandé** pour que le changement de groupe soit bien pris en compte dans toute la session graphique. Une simple déconnexion/reconnexion peut ne pas suffire, notamment en environnement VM.

Vérification :

```bash
groups $USER
# wireshark doit apparaître dans la liste
```

---

# 4. Lancement

```bash
# Interface graphique
wireshark

# En ligne de commande (TShark)
tshark -i eth0
```

> Si TShark n'est pas installé automatiquement avec Wireshark : `sudo apt install tshark`

# 5. ⚠️ Remarques de sécurité

## 5.1. Principe du moindre privilège

Ne **jamais** lancer Wireshark en `root` ou avec `sudo wireshark`. Wireshark analyse des données réseau potentiellement malveillantes — un exploit dans le parseur de protocoles pourrait compromettre le système entier si l'outil tourne en root.

Le mécanisme du groupe `wireshark` délègue uniquement la capacité de capture via les **Linux capabilities** (`CAP_NET_RAW`, `CAP_NET_ADMIN`) sur le binaire `/usr/bin/dumpcap`, sans élever tous les privilèges de l'utilisateur.

```bash
# Vérification des capabilities sur dumpcap
getcap /usr/bin/dumpcap
# Résultat attendu : cap_net_admin,cap_net_raw=eip
```

## 5.2. Contrôle des accès utilisateurs

En environnement scolaire, **n'ajouter au groupe `wireshark` que les utilisateurs qui en ont besoin** :

```bash
# Ajouter un utilisateur spécifique
sudo usermod -aG wireshark nom_utilisateur

# Vérifier les membres du groupe
getent group wireshark
```

## 5.3. Capture sur des interfaces sensibles

Wireshark permet de capturer **tout le trafic visible** sur une interface, y compris celui d'autres machines (mode promiscuous ou switch non segmenté). En établissement scolaire :

- Utiliser des **VLANs** pour isoler les réseaux pédagogiques
- Rappeler aux étudiants que capturer le trafic d'autrui sans autorisation est **illégal** (article 323-1 du Code pénal)
- Préférer des captures sur l'interface **loopback** (`lo`) ou sur un réseau de lab dédié pour les TP

## 5.4. Fichiers de capture `.pcap`

Les fichiers `.pcap` peuvent contenir des données sensibles (credentials en clair, tokens, etc.). En TP :

```bash
# Chiffrer une capture sensible avant stockage/partage
gpg --symmetric capture.pcap

# Ou restreindre les droits
chmod 600 capture.pcap
```

## 5.5. Mises à jour de sécurité

Wireshark est fréquemment mis à jour pour corriger des vulnérabilités dans ses dissecteurs de protocoles. Maintenir à jour régulièrement :

```bash
sudo apt update && sudo apt upgrade wireshark -y
```

# 6. Utilisation de base

## 6.1. 5.1 Lancer une capture sur une interface

**Interface graphique :**

Au démarrage de Wireshark, la liste des interfaces réseau disponibles s'affiche sur l'écran d'accueil. Double-cliquer sur l'interface souhaitée (ex. `eth0`, `ens33`, `wlan0`) pour démarrer la capture immédiatement.

**En ligne de commande (TShark) :**

```bash
# Lister les interfaces disponibles
tshark -D

# Lancer une capture sur une interface
tshark -i eth0

# Capturer en limitant le nombre de paquets
tshark -i eth0 -c 100
```

---

## 6.2. 5.2 Filtres d'affichage après capture

Les **filtres d'affichage** (*display filters*) s'appliquent dans la barre de filtre en haut de la fenêtre Wireshark, **après** la capture. Ils ne suppriment pas les paquets, ils filtrent uniquement l'affichage.

**Filtrer par adresse IP :**

```
# Trafic depuis ou vers une IP
ip.addr == 192.168.1.10

# Trafic depuis une IP source
ip.src == 192.168.1.10

# Trafic vers une IP destination
ip.dst == 192.168.1.10
```

**Filtrer par protocole TCP :**

```
# Tout le trafic TCP
tcp

# TCP sur un port précis (ex. port 443)
tcp.port == 443

# Flags TCP (ex. uniquement les SYN)
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

**Filtrer le trafic HTTP :**

```
# Tout le trafic HTTP (port 80, non chiffré)
http

# Requêtes HTTP GET uniquement
http.request.method == "GET"

# Trafic HTTPS (TLS sur port 443) — le contenu est chiffré
tls
```

> 💡 **Combiner les filtres** avec les opérateurs `&&` (ET), `||` (OU), `!` (NON) :
> ```
> ip.addr == 192.168.1.10 && tcp.port == 80
> ```

**En ligne de commande (TShark) :**

```bash
# Filtrer par IP
tshark -i eth0 -Y "ip.addr == 192.168.1.10"

# Filtrer par protocole HTTP
tshark -i eth0 -Y "http"

# Filtrer TCP port 443
tshark -i eth0 -Y "tcp.port == 443"
```

---

## 6.3. 5.3 Arrêter la capture

**Interface graphique :**

Cliquer sur le bouton **carré rouge** (Stop) dans la barre d'outils, ou utiliser le raccourci clavier `Ctrl+E`.

**En ligne de commande :**

```bash
# Arrêt manuel
Ctrl+C

# Arrêt automatique après N paquets
tshark -i eth0 -c 200

# Arrêt automatique après une durée (en secondes)
tshark -i eth0 -a duration:30
```

---

## 6.4. 5.4 Enregistrer la capture

**Interface graphique :**

`Fichier` → `Enregistrer sous` → choisir le format et le nom du fichier.

Le format recommandé est **`.pcapng`** (plus riche que l'ancien `.pcap` : supporte les métadonnées, les commentaires, les interfaces multiples).

**En ligne de commande (TShark) :**

```bash
# Capturer et enregistrer directement dans un fichier
tshark -i eth0 -w capture.pcapng

# Capturer avec filtre et enregistrer
tshark -i eth0 -f "tcp port 80" -w http_capture.pcapng
```

> ⚠️ L'option `-f` (capture filter) utilise la syntaxe **BPF** (Berkeley Packet Filter), différente des display filters. Elle filtre les paquets **avant** leur enregistrement — les paquets non correspondants ne sont pas capturés du tout.

**Rouvrir une capture enregistrée :**

```bash
# Dans Wireshark
wireshark capture.pcapng

# Dans TShark
tshark -r capture.pcapng
tshark -r capture.pcapng -Y "http"   # avec filtre d'affichage
```

> ⚠️ Penser à restreindre les droits sur les fichiers de capture (voir remarques de sécurité) :
> ```bash
> chmod 600 capture.pcapng
> ```
